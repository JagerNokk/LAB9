# Сквозной проект: аренда квартир в Астане

## Этап 4. Классификация: сдастся ли квартира за 14 дней

Данные: `data/astana_rent_class.csv` — 600 объявлений за август–сентябрь 2026 (учебные данные).

### Целевая переменная

`rented_14`: 1 — квартира сдана в течение 14 дней, 0 — нет. Признак уже бинарный и
важен заказчику (сервису объявлений), поэтому новую цель из числовой переменной строить
не пришлось. Доля класса 1 — 34,2 %, классы несбалансированы, поэтому разбиение
стратифицированное, а accuracy сравнивается с константной моделью (0,66).

Утечка: числовой цели, из которой получен класс, в данных нет. В признаки не включены
`id` (номер объявления не описывает квартиру) и `date`. Цена (`price`) здесь легитимный
признак: арендодатель знает её до публикации и может её менять.

### Что означают ошибки для заказчика

Положительный класс — «квартира сдастся за две недели». Подсказка арендодателю:
«скорее всего сдастся» (прогноз 1) или «есть риск, проверьте цену и фото» (прогноз 0).

- **FP (ложная тревога наоборот: «сдастся», а не сдалась)** — арендодатель успокоен зря,
  не снижает цену и не добавляет фото, квартира простаивает. Это прямая потеря арендодателя
  и доверия к подсказке.
- **FN (пропуск: «есть риск», а квартира сдалась бы)** — арендодатель зря снижает цену или
  тратит время на фото. Потеря меньше: небольшая недополученная аренда.

Дороже FP, поэтому precision важнее recall. Но слишком осторожная модель, которая почти всегда
говорит «есть риск», бесполезна, поэтому пороги сравниваются по F1 при ограничении на precision
(подробнее в разделе про порог).

### Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/train_clf.py     # пишет metrics_clf.json и models/model_clf.joblib
```

`cv_f1` и `cv_roc_auc` — среднее по 5 стратифицированным фолдам обучающей выборки
(`shuffle=True`, `random_state=42`), F1 считается при пороге из `params_clf.json`.
Тестовая выборка для выбора эксперимента не используется.
