# Сквозной проект: аренда квартир в Астане

## Этап 4. Классификация: сдастся ли квартира за 14 дней

Данные: `data/astana_rent_class.csv` — 600 объявлений за август–сентябрь 2026 (учебные данные).

### Целевая переменная

`rented_14`: 1 — квартира сдана в течение 14 дней, 0 — нет. Признак уже бинарный и
важен заказчику (сервису объявлений), поэтому новую цель из числовой переменной строить
не пришлось. Доля класса 1 — 34,2 %, классы несбалансированы, поэтому разбиение
стратифицированное, а accuracy сравнивается с константной моделью (0,66).

Утечка: числовой цели, из которой получен класс, в данных нет. В признаки не включены
`id` (номер объявления не описывает квартиру) и `date`. Цена (`price`) здесь легитимный
признак: арендодатель знает её до публикации и может её менять.

### Что означают ошибки для заказчика

Положительный класс — «квартира сдастся за две недели». Подсказка арендодателю:
«скорее всего сдастся» (прогноз 1) или «есть риск, проверьте цену и фото» (прогноз 0).

- **FP («сдастся», а квартира не сдалась)** — арендодатель успокоен зря, не снижает цену
  и не добавляет фото, квартира простаивает. Это прямая потеря арендодателя и доверия
  к подсказке.
- **FN («есть риск», а квартира сдалась бы)** — арендодатель зря снижает цену или тратит
  время на фото. Потеря меньше: небольшая недополученная аренда.

Принято считать, что FP дороже FN, поэтому precision важнее recall. Но модель, которая почти
всегда говорит «есть риск», бесполезна: ориентир — precision не ниже 0,6 при максимальном F1.

### Запуск

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/train_clf.py     # пишет metrics_clf.json и models/model_clf.joblib
```

`cv_f1` и `cv_roc_auc` — среднее по 5 стратифицированным фолдам обучающей выборки
(`shuffle=True`, `random_state=42`), F1 считается при пороге из `params_clf.json`.
Тестовая выборка для выбора эксперимента не используется. Исследование (П1–П3) —
в `notebooks/clf_lab9.ipynb` (полная версия с выбором порога — в ветке `exp/threshold`).

## Эксперименты: классификация

Все эксперименты ответвлены от одного базового коммита и меняют по одному фактору.

| Ветка | Параметры | cv_f1 | cv_roc_auc | Решение |
|----------------|--------------------------|-------|------------|-----------|
| main | logreg, threshold=0.5 | 0.6034 | 0.8048 | базовая |
| exp/threshold | logreg, threshold=0.45 | 0.6246 | 0.8048 | улучшила, не слита (см. ниже) |
| exp/balanced | logreg, balanced | 0.6392 | 0.8059 | **слита в main, тег v0.4** |
| exp/tree | tree, max_depth=4 | 0.3784 | 0.6188 | хуже базовой, отклонена |

### Выводы

- Лучшая по `cv_f1` — `exp/balanced`. На тесте recall вырос с 0,47 до 0,75, precision упал
  с 0,62 до 0,56. ROC-AUC почти не изменился: веса классов сдвигают порог, а не улучшают
  ранжирование. Тот же эффект даёт порог 0,45, но мягче (precision 0,59, recall 0,53).
- Порог 0,45 выбран на кросс-валидации обучающей выборки: максимальный F1 среди порогов
  с precision ≥ 0,6. Цена ошибок здесь важнее, чем рост F1.
- **Противоречие для заказчика.** По правилу слияния (`cv_f1`) в main попала `balanced`,
  но её precision на тесте (0,56) ниже принятого ориентира 0,6. Если FP действительно
  дороже, стоит взять `exp/threshold` или проверить комбинацию `balanced` + повышенный порог.
  Комбинация в этой работе не проверялась.
- Дерево глубины 4 заметно хуже логистической регрессии (cv_roc_auc 0,62 против 0,80).
- Тест содержит всего 150 объектов (51 положительный): различия в десятые доли precision и
  recall между ветками лежат в пределах случайного разброса.
